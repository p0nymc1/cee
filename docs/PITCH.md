# CEE — 路演版

> 每一节对应一页幻灯片。技术细节见[技术白皮书](WHITEPAPER.md)，这里只讲清楚三件事：**为什么现在**、**我们做了什么**、**凭什么信**。

---

## 1 · 开场：一个真实的两难

某个周二凌晨，安全系统检测到针对 VPN 网关的密码喷洒攻击。

**检测是对的。** 攻击真的在发生，来源 IP 明确，置信度 97%。

自动处置系统按标准流程封锁了那个 IP。

三分钟后，**900 名远程员工全部掉线**——那个"攻击源"是公司自己的 VPN 出口地址。

---

## 2 · 问题不在模型不够聪明

行业目前的答案是"上更强的 Agent"。但上面那个事故里：

- 检测器**没有误报**
- 处置逻辑**没有写错**
- 换一个更聪明的模型，**结果完全一样**

因为问题不在判断，在**执行**。

> **正确的判断，仍然可以有灾难性的执行。**

这就是为什么大量企业买了自动化，却把它设成"只告警、不动手"——**能力买了，不敢用**。

---

## 3 · 现有两条路都走不通

| | 传统企业软件 | LLM Agent |
|---|---|---|
| 追求 | 零故障、可审计 | 零门槛、高智能 |
| 代价 | 每个流程都要人写死 | 黑盒、烧钱、会死循环 |
| 敢不敢碰钱和权限 | 敢 | **不敢** |

企业要的是第三条路：**AI 的适应能力 + 传统软件的可靠性**。

---

## 4 · CEE 的一句话

> **把决策权还给代码，让模型只做它真正擅长的那一件事——把人话变成结构化数据。**

具体是四条：

1. **常规流程由确定性状态机执行**，模型不参与决策，也就不会有幻觉和死循环
2. **危险动作执行前先预演**，探针判定"这一下会波及什么"，不对就转人工并说明原因
3. **等人不算失败**，流程可以挂起几天等审批，重启不丢，且审批不可重放
4. **抽取出来的是猜测不是事实**，模型产出的字段被打上标记，关键动作可以拒绝在猜测值上执行

第 2 条正是开场那个事故的答案：封锁动作执行**之前**，探针会说——

> *这个 IP 是我们自己的 VPN 出口，背后有 900 名远程员工。*

于是它不会被执行，而是转给分析师，附带这句话。

---

## 5 · 一个别人给不了的能力

确定性不只是"不出错"。它还买到一件事：

> **改一条规则之前，先算出它会改变过去哪些决定。**

```
把审批限额从 $100 收紧到 $50
重放一笔已经放行的 $80 退款：
    放行  →  转人工
```

风控调参、阈值收紧、策略变更——今天都是"改完上线看看"。CEE 让它变成**改之前先看**。

Temporal 有持久化，Airflow 有调度，Agent 有智能。**这件事只有确定性引擎做得到。**

## 6 · 凭什么信：现在就能打开

**https://p0nymc1.github.io/cee/**

这个页面由 CI **每小时**在一台干净机器上重新跑出来，包括：

- 六类业务场景的完整执行记录，每一步走了哪条路都在
- 实时行情监控（真实数据，不是演示数据）

**页面上没有一个字是手写的。** 全部是真实运行的输出——这本身就是论据：一个主张"确定性"的项目，展示材料不该靠人工维护。

## 8 · 还差什么（下一阶段买什么）

诚实说清楚，因为这决定了投入的意义：

| 缺口 | 影响 | 需要 |
|---|---|---|
| 没有服务形态 | 现在是库，要嵌进已有系统 | 一层 API 封装 |
| 审批链接是无记名凭证 | 谁拿到谁能批准 | **权限模型（HTTP 化的前置）** |
| 没有可视化编排 | 业务人员改不了流程 | 前端（底层已是纯 JSON 且可校验）|
| 度量偏产出 | 量了省多少调用，没量漏了多少意图 | 诊断性指标 |

**前两项决定能不能进生产，后两项决定能推广多快。**

---

## 9 · 适用边界

不夸大适用范围，这本身是可信度的一部分：

**适合**——有不可逆操作、路径基本明确、需要审计与回溯的流程：
资金操作、权限变更、安全处置、跨系统数据同步。

**不适合**——需要开放式推理的场景。CEE 整套设计就是不让模型做决定，那种场合它只会碍事。纯定时任务是 cron 的活；分布式编排是 Temporal 的活。

---

## 10 · 结束语

在模型能力逐渐趋同的当下，护城河不再是谁的 Prompt 写得好。

> **是谁能让企业敢把权限交给自动化。**

CEE 的答案不是让模型更聪明，而是让它**够不着方向盘**——同时保留它读懂人话的能力。
